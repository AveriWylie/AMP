What AMP 1.0 supports

AMP 1.0 combines model-driven planning with a direct implementation of Minecraft's Java protocol and a live view of the game world.

01 / GAMEPLAY

Move, mine, build, and fight

Pathfinds through loaded terrain, mines in survival or creative, places inventory blocks, and attacks reachable tracked entities.

02 / PLANNING

Guided or autonomous

Accepts single instructions or larger goals, validates model commands, checks results, replans, and accepts instructions mid-task.

03 / WORLD STATE

Understands its surroundings

Tracks terrain, block updates, position, health, food, inventory, selected items, nearby entities, death, and respawn.

04 / MODELS

Cloud or local models

Works with Anthropic or OpenAI-compatible services, including local Ollama, LM Studio, and vLLM endpoints.

05 / LOCAL WORLDS

Safe single-player workflow

Runs a copied world on a local server, manages setup and shutdown, and offers backup-first copy-back when play ends.

06 / CONNECTION

Direct, resilient protocol

Handles Java protocol states, bounded packet decoding, keepalives, server corrections, reconnection, and action confirmation.

Minecraft and server compatibility

AMP 1.0 supports Minecraft Java 26.1, 26.1.1, 26.1.2, and 26.2. Microsoft-authenticated online servers and Java Realms are not enabled because AMP's client identity is still awaiting approval from Minecraft Services.

Before installing

You do not need to modify Minecraft, but you should be comfortable running a command in a terminal and setting an API key or local model address.

Install Python

Use Python 3.10 or newer on Windows, macOS, or Linux.

Choose a model

Use Anthropic or an OpenAI-compatible service such as Ollama, LM Studio, or vLLM.

Choose a world

Connect to an existing offline server or let AMP work from a safe copy of a single-player save.

Limitations

AMP 1.0 is a capable gameplay foundation, not a full replacement for a human player.

  • No crafting, containers, or general inventory management
  • No sprinting, swimming, climbing, doors, or gap jumping
  • No blueprint import or large construction planning
  • Combat only uses entities already visible in loaded world state
  • Navigation targets the standard Java 26 Overworld height range
  • Real model requests may have provider usage costs
